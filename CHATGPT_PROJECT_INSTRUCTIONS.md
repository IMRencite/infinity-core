# Infinity — ChatGPT Project Instructions

Infinity is an autonomous venture discovery, validation, creation, monetization, launch, growth, and optimization system.

Treat the project knowledge files as the canonical architecture and build-state record:

1. `INFINITY_MASTER_ARCHITECTURE.md` — overall architecture and system intent.
2. `INFINITY_BUILD_STATE.md` — authoritative implementation checkpoint and next step.
3. `INFINITY_LOCKED_DECISIONS.md` — architectural invariants that must not be casually regressed.

Before recommending the next implementation step:
- preserve verified systems;
- distinguish VERIFIED from DESIGNED/PLANNED;
- do not rebuild completed systems unless a documented defect requires it;
- maintain Infinity's autonomous-by-default architecture;
- do not reintroduce global human approval;
- design reusable, provider-neutral engines rather than niche-specific hard-coded workflows;
- keep Monetization Engine early enough that economics influence venture selection and build scope;
- use multi-provider collaboration only when the task value justifies the added complexity/cost;
- maintain evidence, economics, quality gates, policy, and traceability.

Organic Growth rules:
- scale quality, not URL count;
- do not equate the 1,000-page digital-real-estate model with a quota;
- no thin/keyword-swapped/location-swapped pages;
- depth follows information need;
- important resources should aim to become credible citation/retrieval resources through information gain, evidence, completeness, and useful structure;
- never invent internal links;
- dynamically derive URL architecture and schema from real site/entity/page context;
- city → neighborhood expansion occurs only when neighborhood-level intent, evidence, uniqueness, quality, and economics justify it;
- HITL is targeted E-E-A-T/evidence enrichment, not a global approval gate;
- never fabricate first-person experience, experts, reviewers, credentials, case studies, or first-party data.

Creative Media rules:
- use a provider-neutral Creative Media Architecture and Media Model Router;
- do not hard-code video to Veo or images to one provider;
- route by capability, quality, cost, latency, and task requirements;
- economically gate media creation;
- prevent low-value AI slop at scale;
- preserve media provenance and cost;
- build future YouTube workflows around research, script, storyboard, shot planning, generation/assembly, quality review, publishing, and performance learning.

Whenever a milestone materially changes verified implementation state or locks a new architectural decision, update the relevant canonical project document(s) so a new chat can continue without depending on old conversation history.

Current next milestone is defined in `INFINITY_BUILD_STATE.md`. Do not assume a planned milestone has been implemented until its verification report is recorded.
