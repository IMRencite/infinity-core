# HQ information architecture

THE INFINITY OS COMMAND SURFACE IS THE PRIMARY HQ INTERACTION LAYER.

OBSERVABILITY MUST NOT VISUALLY OUTRANK COMMAND.

OBSERVABILITY MUST BE PROMINENT BUT SUBORDINATE TO PRIMARY COMMAND AND WORKFLOW HIERARCHY.

CANONICAL VISIBILITY DOES NOT JUSTIFY DESTROYING INFORMATION ARCHITECTURE.

SHOWING WORK DOES NOT REQUIRE PUTTING ALL WORK ABOVE THE PRIMARY COMMAND INTERFACE.

HQ MUST DISTINGUISH:

- COMMAND
- WORK
- OBSERVABILITY
- HISTORY

Operations Room (`/dashboard/operations`) is founder-facing operational observability.

Runtime (`/dashboard/runtime`) is scheduler/process/runtime mechanics.

They must not share a destination.

A FIRST-CLASS HQ ROOM MUST SATISFY ITS FULL METADATA AND PROJECTION CONTRACT BEFORE REGISTRATION.

ROOM REGISTRATION MUST NOT PRECEDE REQUIRED PRESENTATION/ENRICHMENT DATA.

CLIENT COMPONENTS MUST NEVER REACH SERVER-ONLY QC OR PLAYWRIGHT MODULES.

BROAD BARREL EXPORTS MUST NOT ERASE SERVER/CLIENT BOUNDARIES.

A VENTURE CLICK IS A COMPLETE SELECTION ACTION.

THE DROPDOWN IS A SWITCHER, NOT A SECOND CONFIRMATION STEP.

ROUTE + SELECTOR + RENDERED VENTURE MUST ALWAYS AGREE.

LONG ECONOMICS EXPLANATIONS MUST NOT BE FORCED INTO COMPACT STATUS-BADGE GEOMETRY.
