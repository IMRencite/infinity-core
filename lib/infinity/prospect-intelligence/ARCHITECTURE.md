# Prospect Intelligence Foundation V1

Infinity OS owns one canonical persistent commercial intelligence graph.

This is an OS platform capability. It does not belong to Quadrel, Recrea, RealGLP, OccupancyNPV, or any other venture.

## Locked principles

1. Infinity OS owns one canonical persistent Prospect Intelligence graph.
2. Prospect information compounds over time instead of being discarded after campaigns.
3. All authorized Infinity systems consume the shared intelligence through controlled interfaces.
4. Ventures do not own canonical prospect entities. `venture_id` is never stored on Person, Organization, or Entity.
5. New ventures can immediately evaluate the existing graph.
6. Prospect data automatically refreshes and retains historical source observations.
7. Facts, derived attributes, and inference remain distinct.
8. Prospecting continuously replenishes qualified inventory.
9. Sales continuously consumes qualified, communication-eligible inventory whenever outbound capacity exists.
10. Prospecting and outreach remain separate systems.
11. Communication eligibility and suppression always override sales opportunity.
12. Sales outcomes feed Performance Intelligence and improve future prospecting and matching.
13. Private HQ receives a first-class Prospect Intelligence room.
14. `imros.io` receives a matching sanitized public room.
15. Public room activity reflects real runtime activity and never leaks prospect PII.
16. The database is a long-term strategic data asset.

## Flow

```
PUBLIC + LICENSED SOURCES
  → SOURCE REGISTRY → RAW OBSERVATIONS → NORMALIZATION
  → ENTITY RESOLUTION → PERSON + ORGANIZATION GRAPH
  → ENRICHMENT → REFRESH / CHANGE DETECTION
  → VENTURE MATCHING → COMMUNICATION ELIGIBILITY
  → READY SALES INVENTORY → ALWAYS-ON SALES RUNTIME
  → OUTCOMES → PERFORMANCE INTELLIGENCE → LEARNING
```

## Separation

- Prospect Intelligence: who exists, what is known, what changed, which venture may fit.
- Communication eligibility: whether a channel may be used.
- Sales: when to contact, what to send, follow-up.

Canonical consumers use `ProspectIntelligenceService`. Venture-specific canonical silos are forbidden.
